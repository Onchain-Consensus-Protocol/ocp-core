# DLP-1 v2.3 截止时间规则

日期：2026-10-22。仅更新本地候选，不代表部署或上线。保留Genesis 3.6Q/.6Q双池门槛、94.5/4.5/1分账与既有Formal/Core/LP/B经济规则。

## 创建时固定四个节点

令t0为合约创建市场的实际区块时间：

- Genesis截止TG=t0+3小时，由合约计算，用户不能另行指定。
- Formal截止TF由创建者指定，必须晚于TG。
- Core截止TC由创建者指定，必须满足TF+1小时<TC。
- 话题截止TT由创建者指定，必须满足TC<TT。

这里依照用户原文“Formal < Core−1小时”采用严格不等式，恰好相差1小时不通过。Demo默认相对创建时间3/4/6/7小时；后三项可在创建卡填写。实际合约接收绝对Unix秒，Demo输入小时后换算为相对秒数，均创建后固定。

不能允许TF<=TG：否则Genesis末秒合法毕业时Formal可能已经到期。这个顺序约束不额外承诺固定的最短Formal运行时长。

## 开启和关闭

- 只有TG前成功达到原双池门槛，才能原子毕业；Formal和Core在这一刻同时开放。
- 未在TG前毕业，TG同秒及以后进入FAILED；Formal/Core从未开放。R/gToken、B/B-token的既有清算不变。
- 已毕业后到达TG不触发失败。Formal交易要求now<TF；TF同秒及以后停止交易，Core仍可继续质押。
- Core质押要求now<TC；TC同秒及以后可按现有Core规则无许可结算，之后领取。
- TT是话题截止元数据与创建顺序约束，不替代TC、不延后Core结算、不引入事实判断预言机。
- 提前毕业、LP物化/转让、用户交易、同步状态均不能重置四个截止。

快进仍每次10分钟；模拟计时/快进可以到TC后结算，不应为了等待TT延迟结算。Core未开启时显示等待毕业，不能把创建时间当Core开启时间。

## 合约与客户端

Market保存全部截止，Factory/StockFactory将截止传给MarketDeployer；Core Adapter只接收TC，继续检查实际Vault截止一致。创建API新增截止参数，旧四字符串调用不再足够；旧Deployer creation-code store不能用于新Market。

截止校验在任何价格读数、外部部署与资金操作前尽量执行；Market构造也独立验证。先验证uint64时间范围，再计算TG；用安全的先排序再相减检查Core/Formal间隔，避免加法溢出。无新增管理员改时间入口。

前端只在创建时设置后三个截止，市场与Core倒计时继续分开。How页面、股票Demo工厂、测试、Parity参考应与实际模型保持一致。

## 重要非目标

本轮不采用买4.8/卖4.2方向门，不重新分配Genesis资本或LP/B权益，不修改交易费制，不启用真实资金创建，不推送或部署。旧研究中的方向门仍为未批准对照。
