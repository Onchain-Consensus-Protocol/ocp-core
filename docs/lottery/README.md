# OCP 每周协议费抽奖

抽奖使用独立奖池。已部署的市场合约、工厂和 Core 继续照常运行。Keeper 的托管位置待定。

## 规则

| 时间（北京时间） | 操作 |
| --- | --- |
| 周日 20:00 | 确定本周结束的市场和折算价格。纳入正式结算的市场及未毕业并开放退款的市场。 |
| 周日 20:00 至周一 08:00 | Keeper 生成并公开明细。用户可提交交易哈希，由 Keeper 对照链上回执补录合格成交。 |
| 周一 08:00 起 | Keeper 冻结名单、权重和实收奖金。锁定交易会选择至少 15 分钟后的 drand evmnet 轮次，以免使用已公布的随机数。 |
| 下周一 08:00 | 本轮领取截止。已领取的代币退出奖池，未领取的代币归下一位中奖者。 |

每个市场只归入一次。统计参与市场从创建到结束的 Genesis 和正式成交。以当前市场代码对每笔交易实际记账的协议费为准，逐笔计算 `floor(成交基数 × 3 / 1000)`。按抵押代币和钱包累加，再以周日截止时的预定股票代币报价折算权重。Core 质押、市场创建者费用、退款本金及清理尾差均不产生资格。

每轮只抽一位。中奖概率等于该钱包的合格协议费权重除以当期总权重。往期未领取的奖金只增加本期奖金，原有权重不带入下一轮。当期没有合格费用时直接跳过开奖。使用允许的不同股票代币共用一个奖池和中奖人，以原币领取。

## 资金和权限

- 现有协议费收款方可以直接把允许的 ERC-20 转到奖池地址。Keeper 在封账前用 `syncDeposits(token)` 把这笔实收余额记入待分配账本。也可以通过 ERC-20 授权和 `deposit(token, amount)` 立即入账。
- Keeper 只将已到原收款方、在奖池里也已经足额到账的合格协议交易费纳入本轮。每种代币按整数最小单位保管。未到使用时间的资金留在待分配余额。
- 奖池部署时确定 Keeper 和允许的代币。Keeper 能提交一份账本承诺及当期资金分配，但不能改已冻结的账本、提取奖池、单独指定中奖地址或重抽。Keeper 键需备份，生产部署时需选择合适的密钥托管。
- 上链时使用带权重的 Merkle 树。合约验证抽中的号码属于中奖钱包的累计权重区间，验证 drand 签名，并记录领奖地址。提交有效签名和区间证明不需要 Keeper 权限。用户可在冻结前复算公开明细，合约自身无法重读全部历史成交日志。
- 如果签名未能在本轮领取截止前上链，任何人可关闭过期轮次。此实现把已经锁定但未发出的奖金留给未来中奖者，过期轮次的权重失效。若 Keeper 整周未锁定，本周不生成迟到的开奖。历史成交和奖池余额都可公开核对。
- 中奖者可按代币领取部分余额。若某个代币转账失败，可单独领取其他代币。领取已成功的金额不会再次滚入奖池。

## 运行与核对

- 合约在 `contracts/topic-market/src/lottery/`。运行 `forge test --offline --match-contract ProtocolFeeLotteryTest`，测试包含两条真实历史 drand 签名。Robinhood Chain 主网只读模拟验证了正确签名和错误轮次。验签库来自 Randamu `bls-solidity` 的固定版本 `11af179a8287d978659aae07adb66aa60f64b8a6`。该上游实现标为实验性且未经审计。生产启用前需复核验签库和完整开奖的 gas。
- Keeper 的运行方式和环境变量见 `infra/lottery-keeper`。只需要一个能支付链上操作 gas 的 Keeper 钱包。
- 前端启动后可直接打开 `/lottery.html`。设置 `VITE_LOTTERY_CONTRACT` 后显示导航入口。设置 `VITE_LOTTERY_API_URL` 读取公开名单、权重明细和漏单提交接口。前端环境变量是公开值。
