# OCP 抽奖 Keeper

本服务读取 Robinhood Chain（4663）现有主网工厂
`0x05f0fEE5b8460a773872f8e4e9D23aE109BB3592`。它从已确认区块核对官方市场地址、市场结束状态和成交及费用转账事件，生成可公开复算的周奖池账本。Keeper 钱包只需要 gas 和合约授予的提交权。项目方直接把适用代币转入奖池合约。

## 配置和运行

需要 Node.js 22 或以上版本。运行 `npm ci` 安装依赖，然后通过进程环境或本目录的本地 `.env` 设置以下变量。

| 变量 | 用途 |
| --- | --- |
| `ROBINHOOD_RPC_URL` | 第一条 Robinhood 主网历史 RPC，需能读取区块、已确认头、历史合约状态、日志和交易回执 |
| `ROBINHOOD_BACKUP_RPC_URL` | 独立运营方的第二条历史 RPC，Keeper 用它交叉核对链上数据 |
| `LOTTERY_FIRST_CUTOFF` | 首期周日 20:00（北京时间）的 Unix 秒数 |
| `LOTTERY_ADDRESS` | 独立奖池合约地址，读链上抽奖状态和提交开奖使用 |
| `LOTTERY_KEEPER_KEY` | 奖池合约配置的名单提交者私钥。留空时只读取数据，不发送交易 |
| `LOTTERY_DATA_DIR` | 持久数据目录，默认 `./data` |
| `LOTTERY_HOST` | HTTP 监听地址，默认 `127.0.0.1` |
| `LOTTERY_PORT` | HTTP 端口，默认 `8787` |
| `LOTTERY_LOG_SPAN` | 每次日志查询的最大区块范围，默认 5,000 |
| `LOTTERY_MAX_PRICE_AGE` | 当期价格的最大年龄，默认 345,600 秒（96 小时，覆盖周末） |
| `LOTTERY_POLL_SECONDS` | 主循环间隔，默认 60 秒 |

`npm start` 启动服务。保持一份持久数据目录并运行一个提交实例。重启后，服务会根据当前周、保存的数据与合约状态恢复检查。周一锁定已开始的当期名单后，等待原定 drand 轮次，提交同一份证明。整个周窗过期才恢复时，合约停止接受该期新锁定，有待开奖的旧期按合约到期规则处理。

## 归集口径

- 周日 20:00 截止，周一 08:00 停止报漏。时间按北京时间，每个市场按链上进入 `SETTLED` 或 `FAILED` 的那一周统计一次。未毕业失败市场同样计入。
- 从市场创建开始逐笔重放 `GenesisTrade` 和 `FormalTrade`。协议费按原始代币单位对每笔成交计算 `floor(gross × 3 / 1000)`，创建者分成、Core 质押和其他费用不产生抽奖权重。
- 标记实际成功发到协议收款地址的交易费用。未支付交易仍可在明细中核查，但没有资金到账时不计入当期奖池或权重。对账区块为周一 08:00 前最后一个已确认区块，已结算市场截止至该区块成功补发的手续费会计入。某次协议付款会一次支付此前所有未付交易手续费，舍入尘埃单独扣除。
- 同一代币全期使用截止块上历史现价源的同一个美元报价，使用 36 位固定精度整数计算权重，避免拆分导致额外舍入收益。按地址字节顺序构建带权重的 Merkle 树。
- 快照读取不一致、结算事件缺失、费用账本对不上或价格超期时，Keeper 停止提交并输出错误。出现资金不足时，Keeper 保留审计数据，等资金到账后再锁定，受当周交易窗限制。
- 审计请求只接受链上已确认的合法市场成交哈希。单个公共请求核对指定回执，由工作循环批量重建名单。两个 RPC 返回的日志不一致时，Keeper 用规范交易回执交叉复核可见的差异再合并。两方都遗漏的日志仍可能需要用户报漏。

## 公共接口和只读检查

- `GET /snapshot?round=<周日截止的 Unix 秒数>` 读取复核或最终名单，省略参数时返回最近一轮。
- `GET /audit?round=<周日截止的 Unix 秒数>` 下载最终审计 JSON 的原始字节。响应头 `X-Audit-Digest` 是这些字节的 Keccak-256，可和奖池合约锁定值核对。
- `POST /report` 传 `{"transactionHash":"0x…","round":1795348800}`，在复核窗口核查已确认成交回执。新核对通过的回执返回 `202` 和 `queued:true`，随后由工作循环合并。已收录交易的重复提交返回 `added:0`。
- `GET /draw-proof` 取当前已锁定且 drand 已发布的开奖提交参数，其他人也能用这份参数提交开奖。

验证账本时可运行 `npm start -- snapshot <周日截止的 Unix 秒数>`。加 `--review` 可只使用周日截止块之前的到账状态。诊断现有官方市场可运行 `npm start -- inspect-market <市场地址>`。两种命令都不发交易。运行 `npm test` 验证时间边界、费用取整、实际收款和加权证明。

奖池验证 Keeper 提交的承诺和中奖证明。现有市场的历史日志仍由 Keeper 汇总。公开明细和双 RPC 复核用于独立检查名单完整性。
